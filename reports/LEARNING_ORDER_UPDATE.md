# 단어 기본 순서 변경 · 1.0.16+17

2026-11-01. 사용자가 제시한 급수별 학습 단계를 기본 순서로 고정했다. 정렬 선택 UI는 추가하지 않았다. 목록·검색 결과·별표·관련 단어·상세 이전/다음·이어서 학습이 같은 순서를 사용한다. 급수 경계를 넘는 이동과 첫 미학습 단어로 이어서 학습도 유지한다.

단계는 편집 목록과 품사·빈도·JMdict 의미 정보의 규칙으로 배정했다. 같은 단계에서는 wordfreq 3.1.1의 표기별 빈도를 참고한다. 빈도 자료가 없는 항목을 희귀어로 검증했다고 간주하지 않으며 마지막 단계에는 분류 근거가 부족한 항목도 포함한다. 구체적인 규칙·출처·제약은 [학습 순서 문서](../docs/LEARNING_ORDER.md), 단계별 실제 개수와 첫 30개는 [생성 결과](learning-order-data.json)에 기록했다.

## 실제 검증

- `flutter analyze`: 문제 없음.
- `flutter test`: 68개 통과. 전 급수 페이지 순서, 별표·선택·관련 단어의 상대 순서, 네 급수 경계의 양방향 이동, 첫 미학습 단어 이어가기, 구형 콘텐츠에서 업데이트할 때 사용자 백업 전체 보존을 검사했다.
- `python3 -m unittest discover -s pipeline/tests -v`: 45개 통과. 7,811개 누락·중복 없음, 단계·순위 연속성, N4와 실제 N5 ID 연결, 동형 표기 빈도의 과대 적용 방지, 반복 생성, 잘못된 근거 거부 등을 검사했다.
- `python3 pipeline/self_test.py`: 8단어 fixture 기반 가져오기·무결성·선택·JMdict 파서·감사·한국어 템플릿 검사 통과. 전체 JMdict 번역 검수를 의미하지 않는다.
- `python3 pipeline/audit_report.py --db assets/content.sqlite --outdir reports/audit`: SQLite 무결성 `ok`, 외래 키 오류 0.
- Android debug, 범용 release, ARM64 release 빌드 성공. 두 release APK의 기존 배포 인증서, 버전, 비디버그·AOT, ABI, 포함 DB·고지 파일 일치를 확인했다. [APK 검증 기록](learning-order-apk-verification.json).
- 이전 1.0.15 APK의 DB와 비교해 단어 7,811개, 한자 2,756개, 예문 13,718개 및 모든 기존 콘텐츠 테이블 행이 그대로임을 확인했다. 추가한 순서 테이블과 출처 메타데이터만 다르다. 사용자 DB 스키마는 변경하지 않았다.
- Android 16/API 36 x86_64의 별도 에뮬레이터에 1.0.15 범용 release APK를 설치한 뒤 새 release APK를 업데이트 설치했다. 업데이트 전후 사용자 테이블 전체 행이 같았다. Wi-Fi·모바일 데이터를 끈 상태에서 N5 목록의 `する → いる → ある → 人 → いい`, 상세 양방향 이동, 정답 보기 후 진도 증가, 이어서 학습이 다음 미학습 단어 `いる`를 여는 것을 확인했다. [데이터·기기 검증 기록](learning-order-verification.json).
