# JLPT 앱 데이터 설계 변경 사항 — v1.5

## 데이터 원천 확정

- **단어·한자 기본 데이터:** OpenJLPT (N5~N1, 7,811단어/2,383한자, 변경될 수 있음)
- **표기/읽기/품사/사전 연결:** OpenJLPT에서 가져옴. JMdict 원본 XML과 추가 교차 확인
- **한자 음독·훈독:** OpenJLPT의 KANJIDIC2 기반 정보
- **한국어 단어 뜻:** 별도로 작성하여 독립 일본어/한국어 사전과 대조
- **한자 한국식 훈·음:** 별도 한자사전 자료로 작성·확인
- **예문:** OpenJLPT의 Tatoeba 문장 및 후리가나, 한국어 번역은 별도 작성·검수
- **발음 재생:** 모바일 일본어 TTS (원본 음성 무단 수집하지 않음)

## 필수 처리 절차

1. OpenJLPT 공개 원본 ZIP 또는 JSON 다운로드.
2. 필드 정규화: 안정적인 `word_id`, `surface`, `reading_kana`, `level`, `pos`, `jmdict_id`, 예문, 한자 목록.
3. 중복·결측·급수별 건수·DB 무결성 점검.
4. JMdict 원본과 `표기+가나 읽기+사전 ID` 직접 교차 확인.
5. 한국어 뜻 초안 작성. 독립 사전 대조, 의미 구분(다의어), 검토 상태 기록.
6. 한국식 한자 훈음 자료 확보, 사전 출처·검토 상태 기록.
7. 예문 일본어 문장과 문맥 검수 후 한국어 번역 작성·교정.
8. '검수 완료' 레코드와 '초안/미확인' 레코드 구분. 검수 불충분 항목 보고서 출력.
9. 원본 출처·라이선스·Tatoeba 문장 ID 및 판본 해시 보존.
10. 앱 탑재용 콘텐츠 DB와 사용자 DB 분리. 데이터 갱신 시 사용자 기록 유지.

## 사용자 기능과 DB 연계

| 앱 기능 | DB 위치 |
|---|---|
| 급수별 단어 목록/페이지 수 | 콘텐츠 `vocab`, 사용자 `preferences` |
| 전체 페이지 선택·여러 페이지 선택 | 사용자 `selection`, OpenJLPT 안정 `word_id` |
| 한자 상세 및 관련 단어 | 콘텐츠 `kanji`, `word_kanji` |
| 읽기/뜻/훈음/예문 개별 표시·숨김 | `preferences`의 세 가지 visibility 프로필 |
| 별표 | 사용자 `user_word_state` |
| 카드 뒤집기 테스트 및 평가 | 사용자 `test_sessions`, `test_responses` |
| 사전 이중검증 | 콘텐츠 `validations`, `source_review` |

**주의:** 한국어 필드가 검수되지 않은 단어는 완성된 카드로 표시하지 않는다. 일시적인 미리보기에서 초안을 보여주더라도 초안 표시를 유지한다. 한자별 일본어 읽기가 분해 불가능하면 임의로 채우지 않고 미검증으로 둔다.
